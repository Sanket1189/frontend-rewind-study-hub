CSS Cascade, Specificity, Box Model, and Normal Flow

Understand how a CSS value wins and how the browser sizes and places boxes before Flexbox or Grid enters the picture.

1. CSS answers two different questions

CSS must decide:

  1. Which value wins? The cascade, inheritance, specificity, and source order determine the final value of properties such as color or margin.
  2. How is the element laid out? The box model, display type, normal flow, positioning, Flexbox, and Grid determine size and location.

Many CSS bugs happen because these questions are mixed together. First confirm whether the expected declaration wins. Then investigate the layout produced by that declaration.

2. The cascade

The cascade is the browser's conflict-resolution algorithm. When several declarations set the same property on the same element, the browser does not simply choose the selector that looks most complicated.

A practical resolution order is:

  1. Relevance: does the selector match, and is its media query active?
  2. Origin and importance: browser, user, or author CSS; normal or !important.
  3. Cascade layer order, if @layer is used.
  4. Specificity.
  5. Scoping proximity, when @scope is involved.
  6. Source order: if everything else ties, the later declaration wins.

Most application conflicts are resolved by specificity or source order, but those steps only matter after origin, importance, and layer precedence.

3. Inheritance

Some properties naturally pass from a parent to descendants. Text properties commonly inherit: color, font-family, font-size, and line-height.

Layout and box properties normally do not inherit: margin, padding, border, width, and background.

body { color: #172033; font-family: system-ui, sans-serif; }

Most text inside the body receives those values without repetition. A directly targeted value beats an inherited value:

body { color: green; } h1 { color: navy; }

The heading is navy because h1 is targeted directly. A high-specificity parent selector does not make its inherited value stronger than a direct declaration on the child.

Useful keywords are inherit, initial, unset, revert, and revert-layer. They deliberately control how a value falls back instead of duplicating values.

4. Specificity

Specificity compares selectors using three components, written A-B-C:

  • A: ID selectors.
  • B: classes, attributes, and pseudo-classes.
  • C: element selectors and pseudo-elements.
Selector Specificity Reason
button 0-0-1 one element
.button 0-1-0 one class
button.primary 0-1-1 one class and one element
[data-state="open"] 0-1-0 one attribute
#save-button 1-0-0 one ID

Compare from left to right. 1-0-0 beats 0-20-20; this is not a decimal score.

button { background: gray; } .primary-action { background: blue; }

For <button class="primary-action">, blue wins because 0-1-0 beats 0-0-1.

If specificity ties, later source order wins:

.notice { border-color: gray; } .notice { border-color: orange; }

5. Keep specificity low

High specificity makes future changes harder. Prefer a single component class:

.job-card { } .job-card__title { } .job-card--featured { }

Avoid deep selectors such as main .dashboard section article header h2, routine ID styling, and !important escalation. !important changes cascade importance; it is not simply extra specificity.

The :where() pseudo-class is useful for defaults because it always contributes zero specificity:

:where(ul, ol) { margin-block: 0; }

6. The box model

Every rendered element creates one or more boxes. From inside to outside:

  1. Content - text, image, or child content.
  2. Padding - space around the content; the background extends into it.
  3. Border - line around content and padding.
  4. Margin - transparent space outside the border.

With the default box-sizing: content-box, a declared width controls only the content box:

.card { width: 300px; padding: 20px; border: 2px solid; }

The visible width is 300 + 40 + 4 = 344px, before margins.

With box-sizing: border-box, width includes content, padding, and border:

*, *::before, *::after { box-sizing: border-box; }

Now width: 300px stays 300px wide. This global baseline makes sizing easier to reason about.

7. Block and inline display

In normal flow, a block box generally starts on a new line, fills available width when width is auto, and respects width, height, margin, padding, and border.

An inline box continues inside the current line. Explicit width and height do not behave like they do on a block. Horizontal spacing affects the line normally, while vertical padding and border may paint without pushing surrounding lines as expected.

Headings, paragraphs, and sections are block by default. Links, span, strong, and em are inline. inline-block stays inline while accepting width and height.

8. Normal flow

Normal flow is the browser's default layout system:

  • block boxes stack in the block direction;
  • inline boxes flow inside lines of text;
  • document order determines visual and reading order;
  • later content is pushed away by earlier in-flow content.

It is resilient: when text grows, content normally pushes downward rather than overlapping. Preserve normal flow unless another layout model is actually needed.

position: absolute and fixed remove an element from normal flow, so surrounding content reserves no space for it. This is why absolute positioning an entire page causes overlap. position: relative and sticky remain in flow.

9. Margin collapsing

Vertical margins of block elements in normal flow can collapse. Adjacent margins may combine into one margin—usually the larger one—instead of being added.

This commonly surprises developers at adjacent blocks or parent/first-child boundaries. Padding, borders, Flexbox, Grid, or a new block formatting context can prevent particular collapses. Inspect the involved boxes instead of adding random margins.

10. Overflow

When content exceeds a constrained box, the initial behavior is overflow: visible. CSS avoids hiding information by default.

  • visible: content may paint outside.
  • hidden: clip overflow with no user scrolling mechanism.
  • auto: scroll only when necessary.
  • scroll: always provide scrolling.
  • clip: clip without creating a scrolling container.

Avoid fixed heights for text-heavy content unless scrolling is intentional. Prefer content-driven height, min-height, or overflow: auto for genuinely constrained regions.

Common mistakes and fixes

Mistake What happens Better approach
Treating specificity as a decimal Selector results are predicted incorrectly Compare A-B-C left to right
Assuming a nearer ancestor is stronger DOM proximity does not determine specificity Calculate actual selector weight
Adding !important whenever a style loses Overrides become harder and harder Inspect origin, layer, specificity, and order
Forgetting padding and border in width Components unexpectedly overflow Use global border-box
Giving text containers a fixed height Larger or translated text is clipped Prefer natural height or intentional scrolling
Positioning an entire layout absolutely Content overlaps and ignores flow Keep structure in flow; use Flexbox/Grid later
Expecting vertical margins always to add Collapsing margins create different gaps Inspect the formatting context
Using deep DOM selectors Markup changes break styling Use low-specificity component classes

Interview question and model answer

Question: How does the browser decide which CSS rule wins, and how do you debug a style that is not applying?

Model answer:

When declarations conflict, I first check whether the selector matches and whether conditions such as media queries apply. Then I inspect cascade origin, importance, and cascade layers before comparing specificity. Specificity is compared as ID, class/attribute/pseudo-class, and element/pseudo-element components; if it ties, the later declaration wins. I also check whether the value is inherited or directly applied, because a direct declaration beats an inherited value. In DevTools I inspect the computed property and crossed-out declarations to see exactly which rule won. I prefer low-specificity component classes and fix the cascade instead of adding !important. For layout problems, I separately inspect the box model, box-sizing, display type, normal flow, and overflow.
