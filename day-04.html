1. When Grid is the right tool

CSS Grid controls rows and columns together. Choose it when multiple items must share two-dimensional tracks: dashboards, page shells, image galleries, pricing comparisons, or forms with aligned labels and fields.

Flexbox is strongest when the main question is how items relate along one row or column. Grid is strongest when the placement or alignment of both dimensions matters. They are complementary: the finished dashboard uses Grid for the page and card layout, then Flexbox inside small action groups.

2. Grid container and grid items

.dashboard { display: grid; }

The direct children become grid items. Descendants do not participate in that grid unless they create their own layout or use a supported subgrid relationship.

Grid does not replace semantic HTML. The grid container can be main, section, ul, or any suitable element. Choose markup for meaning, then apply layout.

3. Tracks, lines, cells, and areas

  • A track is one row or column.
  • A grid line is a boundary between tracks, numbered from 1.
  • A cell is one row-and-column intersection.
  • A grid area is a rectangular group of one or more cells.
  • A gap is the gutter between tracks.

Grid placement refers to lines, not track numbers. grid-column: 1 / 3 starts at line 1 and ends at line 3, spanning two column tracks.

4. Defining columns and rows

.dashboard { display: grid; grid-template-columns: 15rem minmax(0, 1fr); gap: 1rem; }

The first column is 15rem. The second receives the remaining space but can shrink to zero because of minmax(0, 1fr). A plain 1fr has an automatic minimum that can be influenced by long content, so minmax(0, 1fr) is a useful resilient pattern.

Rows can be explicit too:

.dashboard { grid-template-rows: auto 1fr auto; }

Use explicit tracks for the structure you intentionally design. Let content create additional implicit tracks when the number of items is dynamic.

5. Understanding the fr unit

fr represents a fraction of available space after fixed sizes, intrinsic contributions, and gaps are considered.

grid-template-columns: 1fr 2fr;

The second track receives twice the distributable free space of the first; this does not guarantee that its final rendered width is exactly double in every content situation. Content-based minimum sizes can affect the result.

6. repeat, minmax, auto-fit, and auto-fill

A common responsive card pattern is:

.metric-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 13rem), 1fr)); gap: 1rem; }

repeat() avoids repeating track definitions. minmax() supplies a minimum and maximum. auto-fit creates as many tracks as fit and collapses unused empty tracks, allowing existing items to stretch. auto-fill keeps the empty track slots, which can be useful when the track structure itself should remain visible.

The min(100%, 13rem) minimum prevents a 13rem track from overflowing a container narrower than 13rem.

7. Explicit and implicit grids

Tracks declared with grid-template-columns and grid-template-rows form the explicit grid. When content needs extra rows or columns, the browser creates implicit tracks.

.activity-grid { display: grid; grid-template-columns: repeat(3, 1fr); grid-auto-rows: minmax(8rem, auto); }

grid-auto-rows sizes rows created by auto-placement. Allowing auto as the maximum lets a row grow when content is taller. Avoid fixed row heights for text-heavy content.

8. Auto-placement

Grid places unpositioned items in source order using its auto-placement algorithm. This is ideal for dynamic card collections because new items can enter the next available cell without manual coordinates.

grid-auto-flow: row is the default. The dense keyword may backfill holes, but it can create a visual order that differs from source and keyboard order. Avoid dense packing when sequence matters.

9. Placing items with lines

.activity-panel { grid-column: 1 / -1; }

-1 refers to the final explicit grid line, so the panel spans the whole explicit grid. You can also use span:

.featured-card { grid-column: span 2; }

Use explicit placement for deliberate exceptions. Let auto-placement handle ordinary repeated content.

10. Named lines and grid areas

Named areas make a stable page shell readable:

.page-shell { display: grid; grid-template-areas: "header header" "sidebar main"; grid-template-columns: 15rem minmax(0, 1fr); } .page-header { grid-area: header; } .sidebar { grid-area: sidebar; } .main { grid-area: main; }

Every row in a template must have the same number of cells, and each named area must form a rectangle. Use line-based placement when it is more concise; use named areas when they make a larger layout easier to discuss.

11. Alignment in Grid

Grid uses the box-alignment properties:

  • justify-items: aligns items inside cells on the inline axis.
  • align-items: aligns items inside cells on the block axis.
  • place-items: shorthand for align and justify items.
  • justify-content and align-content: align the entire grid when the grid is smaller than its container.
  • justify-self, align-self, and place-self: override one item.

Most dashboard cards should stretch to fill their cells, which is already the default. Use alignment intentionally rather than centering everything.

12. Content sizing and overflow

Grid items can have content-based minimum sizes. Long strings may widen a track or overflow it. Common fixes include:

.grid-child { min-width: 0; overflow-wrap: anywhere; }

At the track level, minmax(0, 1fr) permits a flexible track to shrink below its min-content contribution. First identify whether the track or the item is enforcing the minimum, then fix the correct layer.

13. Grid areas and accessibility

Visual Grid placement does not change DOM order. Keyboard focus and assistive technology reading order normally follow the source. Keep the HTML in a logical sequence and avoid using placement to create a meaningfully different visual story.

Do not use empty semantic elements as layout spacers. Grid gaps and empty area tokens (.) provide visual spacing without polluting the document.

14. The supplied dashboard

The example demonstrates three Grid levels:

  1. .dashboard-shell creates navigation plus main content.
  2. .metric-grid automatically fits summary cards.
  3. .content-grid creates a wide activity panel and a narrower focus panel.
.content-grid { display: grid; grid-template-columns: minmax(0, 2fr) minmax(15rem, 1fr); gap: 1rem; }

The minmax() values protect both tracks from content overflow. Day 5 will make this structure adapt across viewport and component sizes.

15. Debugging Grid in DevTools

  1. Confirm the correct parent has display: grid.
  2. Identify its direct grid items.
  3. Turn on the Grid overlay to view line numbers, areas, and gaps.
  4. Separate the explicit tracks from automatically created implicit tracks.
  5. Inspect the computed track sizes and content-based minimums.
  6. Check whether an item was explicitly placed or auto-placed.
  7. Look for long content forcing a track wider.
  8. Verify source order remains logical without CSS.
  9. Resize through content failure points.

Common mistakes and fixes

Mistake Result Better approach
Using Grid for a simple button row More machinery than the problem needs Use Flexbox for one dimension
Treating line numbers as column numbers Items span the wrong tracks Remember that placement uses boundaries
Using fixed card columns Layout overflows or leaves wasted space Use repeat(), minmax(), and auto-fit
Using 1fr with long content A track refuses to shrink Try minmax(0, 1fr) and min-width: 0
Fixing row height for text Content clips or overlaps Use minmax(minimum, auto)
Positioning every dynamic card New content requires new coordinates Let auto-placement work
Using dense placement for ordered content Visual and reading order can disagree Preserve source-order placement
Reordering meaningful regions only with CSS Accessibility and visual order diverge Keep the DOM sequence logical

Interview question and model answer

Question: When would you choose CSS Grid over Flexbox, and how would you build a responsive card dashboard?

Model answer:

I choose Grid when rows and columns need to work together or when several items should share the same tracks. Flexbox is usually better for one row or column, such as actions inside a card. For a responsive dashboard I often use repeat(auto-fit, minmax(min(100%, 14rem), 1fr)), which creates as many usable columns as fit without device-specific breakpoints. I use gap for gutters and let auto-placement handle dynamic cards. For fixed page regions I may use named areas or line placement. I watch content-based minimum sizes: minmax(0, 1fr) on tracks and min-width: 0 on children can prevent long content from forcing overflow. I keep DOM order logical because Grid placement changes presentation, not keyboard or screen-reader order.

Quick recall sheet

  • Grid controls rows and columns together.
  • Direct children are grid items.
  • Tracks sit between grid lines.
  • fr shares available space.
  • repeat() removes repeated definitions.
  • minmax() creates resilient track limits.
  • auto-fit collapses unused tracks; auto-fill retains their slots.
  • Auto-placement handles dynamic collections.
  • minmax(0, 1fr) helps flexible tracks shrink.
  • Keep DOM and meaningful visual order aligned.
