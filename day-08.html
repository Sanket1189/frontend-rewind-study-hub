JavaScript Types, Coercion, Truthiness, and Equality

Build a reliable mental model for JavaScript values, conversion, truthiness, equality, and safe defaults.

1. Variables do not have fixed types; values do

JavaScript is dynamically typed. A variable can refer to values of different types at different moments:

let result = 42; // number result = "pending"; // string result = null; // null primitive

This flexibility is useful, but it means input boundaries and conversions must be deliberate. The runtime will sometimes convert values automatically, so frontend bugs often come from assuming a value is already the type its name suggests.

2. The eight JavaScript types

JavaScript has seven primitive types and one object category.

Type Example typeof result Main idea
undefined undefined "undefined" Missing or not assigned
null null "object" Intentional absence; legacy typeof exception
Boolean true "boolean" Logical state
Number 42, NaN "number" Floating-point numeric values
BigInt 42n "bigint" Arbitrarily large integers
String "hello" "string" Text
Symbol Symbol("id") "symbol" Unique identity token
Object {}, [], functions usually "object" Mutable reference value

Functions are callable objects, and typeof functionName returns "function". Arrays are objects, so detect them with Array.isArray(value) rather than typeof.

3. Primitives versus objects

Primitive values are immutable. A string method appears to act on a string, but it returns a new value rather than modifying the original primitive.

const role = "frontend"; const upperRole = role.toUpperCase(); console.log(role); // "frontend" console.log(upperRole); // "FRONTEND"

Objects are reference values. A const object binding cannot be reassigned, but the referenced object's properties can still change.

const profile = { name: "Sanket" }; profile.name = "Sanket K."; // allowed // profile = {}; // TypeError

const protects the binding, not deep object contents.

4. Reference equality

Primitive equality compares values. Object equality compares identity—the reference—not matching structure.

"React" === "React"; // true {} === {}; // false: two different objects [] === []; // false: two different arrays const first = { id: 1 }; const alias = first; first === alias; // true: the same object

JavaScript has no built-in general deep-equality operator. In application code, compare stable identifiers or the specific fields that matter instead of converting whole objects to strings and hoping their structures match.

5. Use typeof carefully

typeof is excellent for most primitives and functions, but it has known edges:

typeof "hello"; // "string" typeof 12; // "number" typeof undefined; // "undefined" typeof null; // "object" — historical behavior typeof []; // "object" typeof function () {}; // "function"

A practical type check often combines tools:

function describe(value) { if (value === null) return "null"; if (Array.isArray(value)) return "array"; return typeof value; }

6. Explicit conversion communicates intent

Prefer explicit conversion at boundaries such as form fields, URL parameters, storage, and API payloads.

const quantityText = "12"; const quantity = Number(quantityText); const label = String(quantity); const hasQuantity = Boolean(quantity);

Number() converts the entire value using numeric conversion rules. parseInt() parses an integer prefix and can accept trailing characters, so it solves a different problem.

Number("12px"); // NaN Number.parseInt("12px", 10); // 12

Choose based on the input contract. A strict quantity field should normally reject "12px", not silently accept the prefix.

7. Implicit coercion and the plus operator

Operators can request conversions. The + operator is especially important because it performs either addition or string concatenation.

2 + 3; // 5 "2" + 3; // "23" 2 + "3"; // "23" "Total: " + 3; // "Total: 3"

If either primitive operand becomes a string, + concatenates. Other arithmetic operators normally request numeric conversion:

"8" - 3; // 5 "8" * 3; // 24 "8" / 2; // 4

Do not use these differences as conversion shortcuts. Convert first, validate, then calculate.

8. NaN is a number value representing failure

NaN means “Not a Number,” but its JavaScript type is still number.

const amount = Number("twelve"); typeof amount; // "number" amount === NaN; // false Number.isNaN(amount); // true

Use Number.isNaN(value) to check this exact numeric failure value. The global isNaN() coerces its argument first and can therefore answer a different question.

9. Truthy and falsy values

Conditions convert a value to Boolean. The falsy values you need in everyday code are:

  • false
  • 0 and -0
  • 0n
  • "" — the empty string
  • null
  • undefined
  • NaN

Every ordinary object is truthy, including empty arrays and empty objects. Non-empty strings are truthy even when their text looks negative.

Boolean([]); // true Boolean({}); // true Boolean("0"); // true Boolean("false"); // true Boolean(""); // false

Do not confuse “falsy” with “loosely equal to false.” They are different language operations.

10. Logical operators return operands

&& and || do not always return Booleans. They short-circuit and return one of their original operands.

"Sanket" && "Dashboard"; // "Dashboard" 0 && loadResults(); // 0; function is not called "" || "Anonymous"; // "Anonymous" "React" || "Fallback"; // "React"

Use Boolean(value) or !!value when you specifically need a Boolean. In UI code, remember that rendering count && component can expose 0 in some rendering systems because the returned value is the number zero, not false.

11. Falsy is broader than nullish

The nullish values are only null and undefined. This difference matters when valid data can be 0, false, or an empty string.

const attempts = 0; attempts || 3; // 3 — replaces the valid zero attempts ?? 3; // 0 — defaults only for null or undefined

Use || when every falsy value means “use the fallback.” Use ?? when only missing nullish data should use the fallback.

12. Strict equality is the default

Strict equality === compares without converting operands. Different types are unequal.

3 === 3; // true 3 === "3"; // false false === 0; // false null === undefined; // false

Loose equality == applies a conversion algorithm before comparison. It can produce results that are difficult to understand during a quick code review.

0 == false; // true "" == 0; // true "0" == false; // true null == undefined; // true

Prefer === and !==. An intentional value == null is sometimes used to match both null and undefined, but it should be a deliberate team convention, not an accidental shortcut.

13. Object.is and special numeric cases

Object.is() mostly resembles strict equality but differs for NaN and signed zero.

NaN === NaN; // false Object.is(NaN, NaN); // true 0 === -0; // true Object.is(0, -0); // false

Most business comparisons should still use ===. Use Object.is() when those exact special cases matter. React also uses Object.is semantics in several change comparisons, which makes this distinction useful later.

14. Null and undefined

Both represent absence, but they commonly communicate different origins:

  • undefined often means no value was supplied, assigned, found, or returned.
  • null often means absence was deliberately represented.
let selectedRole; // undefined document.querySelector(".missing"); // null

Choose a clear convention inside your own data model. At external boundaries, expect either and normalize them if the distinction does not matter.

15. A safe input-boundary pattern

Browser inputs produce strings, even for many fields that appear numeric. Convert and validate once near the boundary.

function parseYearsExperience(rawValue) { const value = Number(rawValue); if (!Number.isFinite(value) || value < 0) { return { ok: false, error: "Enter zero or a positive number." }; } return { ok: true, value }; }

The rest of the application can now consume a validated number instead of repeating coercion assumptions.

16. Predict code in three steps

When an output question looks strange, do not guess. Trace it:

  1. Identify the type and value of each operand.
  2. Identify which conversion the operator requests.
  3. Apply the operator to the converted values.

For [] == false:

  1. The operands are an object and a Boolean.
  2. Loose equality converts the object toward a primitive and the Boolean toward a number.
  3. The empty array becomes an empty string, then zero; false becomes zero, so the comparison is true.

The important production lesson is not to memorize the puzzle. It is to use strict equality and explicit conversion so application intent remains visible.

Common mistakes and fixes

Mistake Result Better approach
Assuming form values are numbers "2" + "3" becomes "23" Convert and validate at the input boundary
Using typeof null as the only null test Null is reported as object Check value === null first
Testing arrays with typeof Arrays are reported as objects Use Array.isArray()
Comparing separate object literals Matching structure still returns false Compare identity, IDs, or chosen fields
Defaulting counts with logical OR Valid zero becomes the fallback Use ?? for nullish defaults
Checking value === NaN It always returns false Use Number.isNaN(value)
Using == casually Hidden conversion complicates results Prefer strict equality
Assuming logical operators return Boolean UI receives an operand such as 0 Convert explicitly when Boolean output is required

Interview question and model answer

Question: Explain JavaScript coercion, truthiness, and the difference between == and ===.

Model answer:

JavaScript values have types, while variables can be rebound to values of different types. Coercion is conversion from one type to another; it can be explicit through Number, String, or Boolean, or implicit when an operator requests it. In a Boolean context, only the defined falsy values become false; objects, including empty arrays and objects, are truthy. Logical && and || short-circuit and return operands rather than guaranteed Booleans. Loose equality performs type conversion before comparison, while strict equality does not, so I use === by default. I convert and validate external string inputs at their boundary, use ?? when zero, false, or an empty string are valid, use Number.isNaN for numeric conversion failure, and compare objects by identity or explicit fields rather than structure.

Quick recall sheet

  • JavaScript has seven primitive types plus Object.
  • typeof null is "object"; arrays also need a separate check.
  • Primitives are immutable; objects are reference values.
  • const prevents rebinding, not object mutation.
  • Convert input strings explicitly before arithmetic.
  • + can add or concatenate; other arithmetic operators usually convert to numbers.
  • NaN has type number and is detected with Number.isNaN().
  • Empty arrays and objects are truthy.
  • && and || return operands.
  • ?? defaults only null and undefined.
  • Prefer ===; object equality compares references.
  • Object.is() differs from === for NaN and signed zero.
